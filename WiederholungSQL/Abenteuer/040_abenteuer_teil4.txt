QUEST 1 - DISTINCT
--------------------------------------------------

Der Gildenmeister möchte wissen:

Welche verschiedenen Schwierigkeitsstufen gibt es bei den Aufträgen?

Wenn du einfach schreibst:

SELECT schwierigkeit
FROM auftraege;

bekommst du Werte mehrfach angezeigt.

Zum Beispiel:

leicht
schwer
mittel
schwer
leicht
mittel
mittel


Mit DISTINCT kannst du doppelte Ergebnisse entfernen.


Beispiel:

SELECT DISTINCT schwierigkeit
FROM auftraege;


Das Ergebnis wäre:

leicht
mittel
schwer


SQL-Wissen:

DISTINCT bedeutet:
Zeige jeden unterschiedlichen Wert nur einmal.


AUFGABE:

Finde mit DISTINCT heraus, welche verschiedenen Statuswerte bei den Abenteurern vorkommen.

QUEST 2 - DIE SUCHE MIT LIKE
--------------------------------------------------

Der Bibliothekar erinnert sich nur noch daran, dass ein Auftrag irgendetwas mit "Bug" im Namen hatte.

Mit LIKE kannst du nach Textmustern suchen.


Beispiel:

SELECT *
FROM auftraege
WHERE titel LIKE '%Bug%';


Das Prozentzeichen % ist ein Platzhalter.

Es bedeutet:
Hier können beliebig viele Zeichen stehen.


Beispiele:
LIKE 'Der%'

Bedeutet:
Der Text beginnt mit "Der".


LIKE '%Dungeon'

Bedeutet:
Der Text endet mit "Dungeon".


LIKE '%Bug%'

Bedeutet:
Irgendwo im Text steht "Bug".


AUFGABE:
Finde alle Aufträge, deren Titel mit "Der" beginnt.


BONUS:
Finde alle Artefakte, deren Name irgendwo das Wort "der" enthält.

QUEST 7 - CASE WHEN
--------------------------------------------------

Der Gildenmeister möchte Abenteurer automatisch bewerten.

Die Regeln:

Level 1 bis 3  = Anfänger
Level 4 bis 6  = Erfahren
Level 7 bis 9  = Veteran
Level 10+      = Legende


Dafür gibt es CASE WHEN.


Beispiel:

SELECT
    name,
    level,
    CASE
        WHEN level <= 3 THEN 'Anfänger'
        WHEN level <= 6 THEN 'Erfahren'
        WHEN level <= 9 THEN 'Veteran'
        ELSE 'Legende'
    END AS rang
FROM abenteurer;


SQL-Wissen:

CASE funktioniert ähnlich wie:

Wenn Bedingung A stimmt, dann Wert A.
Wenn Bedingung B stimmt, dann Wert B.
Sonst ein anderer Wert.

QUEST 9 - TABELLEN-ALIASES
--------------------------------------------------

Unsere Abfragen werden langsam ziemlich lang.

Statt ständig:

auftraege.titel
artefakte.name

zu schreiben, können Tabellen ebenfalls Aliases bekommen.


Beispiel:

SELECT
    a.name,
    au.titel
FROM abenteurer AS a
JOIN auftraege AS au
ON a.id = au.abenteurer_id;


Jetzt steht:

a

für:

abenteurer


Und:

au

für:

auftraege


AUFGABE:

Verbinde alle drei Tabellen erneut.

Verwende:

a  = abenteurer
au = auftraege
ar = artefakte


Gib aus:

a.name
au.titel

QUEST 10 - TRANSAKTIONEN
--------------------------------------------------

Der Schatzmeister muss große Änderungen durchführen.

Er möchte allen aktiven Abenteurern 100 Gold geben.

Doch was passiert, wenn er einen Fehler macht?


Dafür gibt es Transaktionen.


Ein vereinfachtes Beispiel:

START TRANSACTION;

UPDATE abenteurer
SET gold = gold + 100
WHERE status = 'aktiv';


Jetzt wurde die Änderung innerhalb der Transaktion durchgeführt.

Sie kann bestätigt werden mit:

COMMIT;


Oder rückgängig gemacht werden mit:

ROLLBACK;


SQL-Wissen:

COMMIT

bedeutet:

Änderungen endgültig bestätigen.


ROLLBACK

bedeutet:

Änderungen der aktuellen Transaktion rückgängig machen.


Wichtig:

Die genaue Syntax für Transaktionen kann je nach Datenbanksystem etwas unterschiedlich sein.

--------------------------------------------------
GEHEIM-QUEST - WAS IST SQL INJECTION?
--------------------------------------------------

Nach dem Kampf untersucht der Archivmeister die Nachricht von Bobby Tables.

Sie sah ungefähr so aus:

Robert'); DROP TABLE abenteurer;--


Das ist eine Anspielung auf ein bekanntes Programmierer-Meme.

Das Problem dahinter heißt:

SQL Injection


SQL Injection kann entstehen, wenn ein Programm Benutzereingaben unsicher direkt in SQL-Befehle einfügt.


Vereinfacht gesagt:

Ein Programm erwartet einen Namen.

Ein Angreifer versucht stattdessen, Teile eines SQL-Befehls einzugeben.


Deshalb sollte man SQL-Abfragen in echten Anwendungen nicht einfach durch das Zusammenkleben von Texteingaben bauen.


Stattdessen verwendet man normalerweise:

Prepared Statements

oder:

parametrisierte Abfragen


Beispielidee:

SELECT *
FROM abenteurer
WHERE name = ?;


Das ? steht für einen Wert, der später sicher übergeben wird.


Wichtig:

Wie Parameter genau geschrieben werden, hängt von der Programmiersprache und Datenbank ab.


--------------------------------------------------
NERD-WISSEN: WARUM "BOBBY TABLES"?
--------------------------------------------------

"Bobby Tables" ist ein berühmter Witz aus der Programmiererwelt.

Dabei wird das Thema SQL Injection anhand eines ungewöhnlichen Namens erklärt.

Die eigentliche Lektion dahinter ist ernst:
Benutzereingaben dürfen nicht blind als SQL-Code behandelt werden.

ERKLÄRUNGEN:

A = Änderungen einer Transaktion rückgängig machen

B = Werte innerhalb eines Bereichs suchen

C = doppelte Ergebnisse entfernen

D = mehrere mögliche Werte prüfen

E = Änderungen einer Transaktion bestätigen

F = Alias bzw. Anzeigenamen vergeben

G = Textmuster suchen

H = Bedingungen verwenden, um unterschiedliche Werte auszugeben


Schreibe die Lösung zum Beispiel so:

2 = ?
3 = ?
