--------------------------------------------------

Eine alte Mission wurde versehentlich doppelt eingetragen.

Mit DELETE kannst du Datensätze entfernen.


Beispiel:

    DELETE FROM missionen
    WHERE id = 5;


SQL-WISSEN:

DELETE FROM entfernt Datensätze aus einer Tabelle.


ACHTUNG:

    DELETE FROM missionen;

würde ALLE Missionen löschen.

Deshalb sollte man bei DELETE besonders auf WHERE achten.

--------------------------------------------------
QUEST 4 - DER PRIMARY KEY
--------------------------------------------------

Du hast bereits mehrfach die Spalte "id" verwendet.

Aber warum ist sie so wichtig?

In unserer Tabelle steht:

    id INT PRIMARY KEY


PRIMARY KEY bedeutet:

Der Wert identifiziert einen Datensatz eindeutig.


Beispiel:

    id = 1

darf nur einmal vorkommen.


Folgendes wäre also problematisch:

id | name
---|-------
1  | Rexi
1  | Spike


Die Datenbank könnte nicht eindeutig erkennen,
welcher Datensatz gemeint ist.


SQL-WISSEN:

Ein PRIMARY KEY sollte:

    - eindeutig sein
    - nicht NULL sein
    - einen Datensatz eindeutig identifizieren


--------------------------------------------------
QUEST 5 - DER FOREIGN KEY
--------------------------------------------------

Unsere Tabelle "missionen" besitzt:

    dinosaurier_id


Diese Spalte verweist auf:

    dinosaurier.id


Eine solche Verbindung kann mit einem FOREIGN KEY
abgesichert werden.


Beispiel:

    CREATE TABLE missionen (
        id INT PRIMARY KEY,
        titel VARCHAR(100),
        schwierigkeit VARCHAR(20),
        belohnung INT,
        dinosaurier_id INT,
        FOREIGN KEY (dinosaurier_id)
            REFERENCES dinosaurier(id)
    );


SQL-WISSEN:

PRIMARY KEY:

    Identifiziert einen Datensatz.


FOREIGN KEY:

    Verweist auf einen Datensatz in einer anderen Tabelle.


Dadurch entstehen Beziehungen zwischen Tabellen.


--------------------------------------------------
QUEST 6 - DAS GEHEIMNIS DES LEFT JOIN
--------------------------------------------------

Du kennst bereits:

    JOIN


Ein normaler JOIN zeigt nur Datensätze,
für die eine passende Verbindung existiert.

Aber was passiert mit Dinosauriern,
denen keine Mission zugeordnet wurde?


Hier kommt LEFT JOIN ins Spiel.


Beispiel:

    SELECT dinosaurier.name, missionen.titel
    FROM dinosaurier
    LEFT JOIN missionen
    ON dinosaurier.id = missionen.dinosaurier_id;


LEFT JOIN bedeutet:

Zeige ALLE Datensätze der linken Tabelle.

Auch wenn kein passender Datensatz in der rechten
Tabelle existiert.


In diesem Beispiel ist:

    dinosaurier = linke Tabelle
    missionen   = rechte Tabelle


Hat ein Dinosaurier keine Mission, steht beim Titel
möglicherweise:

    NULL


AUFGABE:

Zeige mit LEFT JOIN:

    name
    art
    titel

für alle Dinosaurier.

Auch Dinosaurier ohne Mission sollen angezeigt werden.

--------------------------------------------------
QUEST 8 - HAVING
--------------------------------------------------

Die Forschungsleitung möchte wissen:

Welche Dinosaurier kommen in MEHR ALS EINER Mission vor?


Wir kennen bereits:

    GROUP BY


Beispiel:

    SELECT dinosaurier.name, COUNT(missionen.id)
    FROM dinosaurier
    JOIN missionen
    ON dinosaurier.id = missionen.dinosaurier_id
    GROUP BY dinosaurier.name;


Aber wie filtern wir das Ergebnis von COUNT()?


Dafür gibt es:

    HAVING


Beispiel:

    SELECT dinosaurier.name, COUNT(missionen.id)
    FROM dinosaurier
    JOIN missionen
    ON dinosaurier.id = missionen.dinosaurier_id
    GROUP BY dinosaurier.name
    HAVING COUNT(missionen.id) > 1;


SQL-WISSEN:

WHERE filtert einzelne Datensätze.

HAVING filtert Gruppen.


Merksatz:

    WHERE kommt normalerweise vor GROUP BY.

    HAVING kommt nach GROUP BY.


--------------------------------------------------
QUEST 9 - DIE UNTERABFRAGE
--------------------------------------------------

Die Forschungsleitung stellt eine schwierige Frage:

Welche Dinosaurier sind schwerer als der
durchschnittliche Dinosaurier?


Zuerst können wir den Durchschnitt berechnen:

    SELECT AVG(gewicht)
    FROM dinosaurier;


Aber wir können diese Abfrage auch in eine andere
Abfrage einbauen.


Beispiel:

    SELECT name, gewicht
    FROM dinosaurier
    WHERE gewicht > (
        SELECT AVG(gewicht)
        FROM dinosaurier
    );


Das nennt man:

    Unterabfrage

oder:

    Subquery


Die innere Abfrage berechnet zuerst:

    SELECT AVG(gewicht)
    FROM dinosaurier;


Danach verwendet die äußere Abfrage dieses Ergebnis.


AUFGABE:

Finde alle Dinosaurier, deren Alter über dem
durchschnittlichen Alter aller Dinosaurier liegt.

LEFT JOIN:

    Zeigt alle Datensätze der linken Tabelle,
    auch wenn rechts keine Verbindung existiert.

    Filtert Datensätze.
