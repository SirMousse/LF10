QUEST 3 - DER VERBOTENE DELETE-BEFEHL
--------------------------------------------------

Ein alter Auftrag wurde versehentlich doppelt eingetragen.

Professor Dumbledore befiehlt:

    "Entferne ihn aus dem Archiv!"

Mit DELETE kannst du Datensätze entfernen.


Beispiel:

    DELETE FROM auftraege
    WHERE id = 5;


SQL-WISSEN:

DELETE FROM entfernt Datensätze aus einer Tabelle.


ACHTUNG:

    DELETE FROM auftraege;

würde ALLE Aufträge löschen.

Deshalb sollte man bei DELETE besonders auf WHERE achten.

--------------------------------------------------
QUEST 4 - DER PRIMARY KEY
--------------------------------------------------

Du hast bereits mehrfach die Spalte "id" verwendet.

Aber warum ist sie so wichtig?

In unserer Tabelle steht:

    id INT PRIMARY KEY


PRIMARY KEY bedeutet:

Der Wert identifiziert einen Datensatz eindeutig.


Beispiel:

    id = 1

darf nur einmal vorkommen.


Folgendes wäre also problematisch:

id | name
---|---------
1  | Harry
1  | Hermine


Die Datenbank könnte nicht eindeutig erkennen,
welcher Datensatz gemeint ist.


SQL-WISSEN:

Ein PRIMARY KEY sollte:

    - eindeutig sein
    - nicht NULL sein
    - einen Datensatz eindeutig identifizieren


--------------------------------------------------
QUEST 5 - DER FOREIGN KEY
--------------------------------------------------

Unsere Tabelle "auftraege" besitzt:

    schueler_id


Diese Spalte verweist auf:

    zauberschueler.id


Eine solche Verbindung kann mit einem FOREIGN KEY
abgesichert werden.


Beispiel:

    CREATE TABLE auftraege (
        id INT PRIMARY KEY,
        titel VARCHAR(100),
        schwierigkeit VARCHAR(20),
        belohnung INT,
        schueler_id INT,
        FOREIGN KEY (schueler_id)
            REFERENCES zauberschueler(id)
    );


SQL-WISSEN:

PRIMARY KEY:

    Identifiziert einen Datensatz.


FOREIGN KEY:

    Verweist auf einen Datensatz in einer anderen Tabelle.


Dadurch entstehen Beziehungen zwischen Tabellen.


--------------------------------------------------
QUEST 6 - DAS GEHEIMNIS DES LEFT JOIN
--------------------------------------------------

Du kennst bereits:

    JOIN


Ein normaler JOIN zeigt nur Datensätze,
für die eine passende Verbindung existiert.

Aber was passiert mit Zauberschülern,
die noch keinen Auftrag haben?


Hier kommt LEFT JOIN ins Spiel.


Beispiel:

    SELECT zauberschueler.name, auftraege.titel
    FROM zauberschueler
    LEFT JOIN auftraege
    ON zauberschueler.id = auftraege.schueler_id;


LEFT JOIN bedeutet:

Zeige ALLE Datensätze der linken Tabelle.

Auch wenn kein passender Datensatz in der rechten
Tabelle existiert.


In diesem Beispiel ist:

    zauberschueler = linke Tabelle
    auftraege      = rechte Tabelle


Hat ein Zauberschüler keinen Auftrag, steht beim Titel
möglicherweise:

    NULL


AUFGABE:

Zeige mit LEFT JOIN:

    name
    haus
    titel

für alle Zauberschüler.

Auch Zauberschüler ohne Auftrag sollen angezeigt werden.

--------------------------------------------------
QUEST 8 - HAVING
--------------------------------------------------

Professor Dumbledore möchte wissen:

Welche Zauberschüler haben MEHR ALS EINEN Auftrag?


Wir kennen bereits:

    GROUP BY


Beispiel:

    SELECT zauberschueler.name, COUNT(auftraege.id)
    FROM zauberschueler
    JOIN auftraege
    ON zauberschueler.id = auftraege.schueler_id
    GROUP BY zauberschueler.name;


Aber wie filtern wir das Ergebnis von COUNT()?


Dafür gibt es:

    HAVING


Beispiel:

    SELECT zauberschueler.name, COUNT(auftraege.id)
    FROM zauberschueler
    JOIN auftraege
    ON zauberschueler.id = auftraege.schueler_id
    GROUP BY zauberschueler.name
    HAVING COUNT(auftraege.id) > 1;


SQL-WISSEN:

WHERE filtert einzelne Datensätze.

HAVING filtert Gruppen.


Merksatz:

    WHERE kommt normalerweise vor GROUP BY.

    HAVING kommt nach GROUP BY.


--------------------------------------------------
QUEST 9 - DIE UNTERABFRAGE
--------------------------------------------------

Professor Dumbledore stellt eine schwierige Frage:

Welche Zauberschüler besitzen mehr Punkte als
der durchschnittliche Zauberschüler?


Zuerst können wir den Durchschnitt berechnen:

    SELECT AVG(punkte)
    FROM zauberschueler;


Aber wir können diese Abfrage auch in eine andere
Abfrage einbauen.


Beispiel:

    SELECT name, punkte
    FROM zauberschueler
    WHERE punkte > (
        SELECT AVG(punkte)
        FROM zauberschueler
    );


Das nennt man:

    Unterabfrage

oder:

    Subquery


Die innere Abfrage berechnet zuerst:

    SELECT AVG(punkte)
    FROM zauberschueler;


Danach verwendet die äußere Abfrage dieses Ergebnis.
