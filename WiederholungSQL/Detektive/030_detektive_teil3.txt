QUEST 3 - DER GEFÄHRLICHE DELETE-BEFEHL
--------------------------------------------------

Eine alte Ermittlung wurde versehentlich doppelt eingetragen.

Der Chefermittler sagt:

    "Diese Fallakte muss aus dem Archiv verschwinden!"

Mit DELETE kannst du Datensätze entfernen.


Beispiel:

    DELETE FROM ermittlungen
    WHERE id = 5;


SQL-WISSEN:

DELETE FROM entfernt Datensätze aus einer Tabelle.


ACHTUNG:

    DELETE FROM ermittlungen;

würde ALLE Ermittlungen löschen.

Deshalb sollte man bei DELETE besonders auf WHERE achten.

--------------------------------------------------
QUEST 4 - DER PRIMARY KEY
--------------------------------------------------

Du hast bereits mehrfach die Spalte "id" verwendet.

Aber warum ist sie so wichtig?

In unserer Tabelle steht:

    id INT PRIMARY KEY


PRIMARY KEY bedeutet:

Der Wert identifiziert einen Datensatz eindeutig.


Beispiel:

    id = 1

darf nur einmal vorkommen.


Folgendes wäre also problematisch:

id | name
---|-------
1  | Mira
1  | Jonas


Die Datenbank könnte nicht eindeutig erkennen,
welcher Datensatz gemeint ist.


SQL-WISSEN:

Ein PRIMARY KEY sollte:

    - eindeutig sein
    - nicht NULL sein
    - einen Datensatz eindeutig identifizieren


--------------------------------------------------
QUEST 5 - DER FOREIGN KEY
--------------------------------------------------

Unsere Tabelle "ermittlungen" besitzt:

    detektiv_id


Diese Spalte verweist auf:

    detektive.id


Eine solche Verbindung kann mit einem FOREIGN KEY
abgesichert werden.


Beispiel:

    CREATE TABLE ermittlungen (
        id INT PRIMARY KEY,
        titel VARCHAR(100),
        schwierigkeit VARCHAR(20),
        belohnung INT,
        detektiv_id INT,
        FOREIGN KEY (detektiv_id)
            REFERENCES detektive(id)
    );


SQL-WISSEN:

PRIMARY KEY:

    Identifiziert einen Datensatz.


FOREIGN KEY:

    Verweist auf einen Datensatz in einer anderen Tabelle.


Dadurch entstehen Beziehungen zwischen Tabellen.


--------------------------------------------------
QUEST 6 - DAS GEHEIMNIS DES LEFT JOIN
--------------------------------------------------

Du kennst bereits:

    JOIN


Ein normaler JOIN zeigt nur Datensätze,
für die eine passende Verbindung existiert.

Aber was passiert mit Detektiven,
die noch keine Ermittlung haben?


Hier kommt LEFT JOIN ins Spiel.


Beispiel:

    SELECT detektive.name, ermittlungen.titel
    FROM detektive
    LEFT JOIN ermittlungen
    ON detektive.id = ermittlungen.detektiv_id;


LEFT JOIN bedeutet:

Zeige ALLE Datensätze der linken Tabelle.

Auch wenn kein passender Datensatz in der rechten
Tabelle existiert.


In diesem Beispiel ist:

    detektive     = linke Tabelle
    ermittlungen  = rechte Tabelle


Hat ein Detektiv keine Ermittlung, steht beim Titel
möglicherweise:

    NULL


AUFGABE:

Zeige mit LEFT JOIN:

    name
    spezialgebiet
    titel

für alle Detektive.

Auch Detektive ohne Ermittlung sollen angezeigt werden.

--------------------------------------------------
QUEST 8 - HAVING
--------------------------------------------------

Der Chefermittler möchte wissen:

Welche Detektive haben MEHR ALS EINE Ermittlung übernommen?


Wir kennen bereits:

    GROUP BY


Beispiel:

    SELECT detektive.name, COUNT(ermittlungen.id)
    FROM detektive
    JOIN ermittlungen
    ON detektive.id = ermittlungen.detektiv_id
    GROUP BY detektive.name;


Aber wie filtern wir das Ergebnis von COUNT()?


Dafür gibt es:

    HAVING


Beispiel:

    SELECT detektive.name, COUNT(ermittlungen.id)
    FROM detektive
    JOIN ermittlungen
    ON detektive.id = ermittlungen.detektiv_id
    GROUP BY detektive.name
    HAVING COUNT(ermittlungen.id) > 1;


SQL-WISSEN:

WHERE filtert einzelne Datensätze.

HAVING filtert Gruppen.


Merksatz:

    WHERE kommt normalerweise vor GROUP BY.

    HAVING kommt nach GROUP BY.


--------------------------------------------------
QUEST 9 - DIE UNTERABFRAGE
--------------------------------------------------

Der Chefermittler stellt eine schwierige Frage:

Welche Detektive haben mehr Erfolge als
der durchschnittliche Detektiv?


Zuerst können wir den Durchschnitt berechnen:

    SELECT AVG(erfolge)
    FROM detektive;


Aber wir können diese Abfrage auch in eine andere
Abfrage einbauen.


Beispiel:

    SELECT name, erfolge
    FROM detektive
    WHERE erfolge > (
        SELECT AVG(erfolge)
        FROM detektive
    );


Das nennt man:

    Unterabfrage

oder:

    Subquery


Die innere Abfrage berechnet zuerst:

    SELECT AVG(erfolge)
    FROM detektive;


Danach verwendet die äußere Abfrage dieses Ergebnis.


AUFGABE:

Finde alle Detektive, deren Anzahl an Fällen über der
durchschnittlichen Anzahl aller Fälle liegt.

Außerdem kennst du inzwischen den Unterschied zwischen:

    JOIN
    und
    LEFT JOIN


JOIN:

    Zeigt nur passende Datensätze aus beiden Tabellen.


LEFT JOIN:

    Zeigt alle Datensätze der linken Tabelle,
    auch wenn rechts keine Verbindung existiert.


Du kennst außerdem:

WHERE:

    Filtert Datensätze.


HAVING:

    Filtert Gruppen.
