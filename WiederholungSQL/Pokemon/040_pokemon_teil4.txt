--------------------------------------------------
QUEST 1 - DISTINCT
--------------------------------------------------

Professor Eich möchte wissen:

Welche verschiedenen Schwierigkeitsstufen gibt es
bei den Missionen?

Wenn du einfach schreibst:

    SELECT schwierigkeit
    FROM missionen;

bekommst du Werte mehrfach angezeigt.


Mit DISTINCT kannst du doppelte Ergebnisse entfernen.


Beispiel:

    SELECT DISTINCT schwierigkeit
    FROM missionen;


Das Ergebnis wäre:

    leicht
    mittel
    schwer


SQL-WISSEN:

DISTINCT bedeutet:

    Zeige jeden unterschiedlichen Wert nur einmal.


AUFGABE:

Finde mit DISTINCT heraus, welche verschiedenen
Pokémon-Typen in der Datenbank vorkommen.


--------------------------------------------------
QUEST 2 - DIE SUCHE MIT LIKE
--------------------------------------------------

Professor Eich erinnert sich nur noch daran,
dass eine Mission irgendetwas mit "Geheimnis"
im Titel hatte.

Mit LIKE kannst du nach Textmustern suchen.


Beispiel:

    SELECT *
    FROM missionen
    WHERE titel LIKE '%Geheimnis%';


Das Prozentzeichen % ist ein Platzhalter.

Es bedeutet:

    Hier können beliebig viele Zeichen stehen.


Beispiele:

    LIKE 'Das%'

Bedeutet:

    Der Text beginnt mit "Das".


    LIKE '%Vulkan'

Bedeutet:

    Der Text endet mit "Vulkan".


    LIKE '%Geheimnis%'

Bedeutet:

    Irgendwo im Text steht "Geheimnis".


AUFGABE:

Finde alle Missionen, deren Titel mit "Das" beginnt.


BONUS:

Finde alle Items, deren Name irgendwo
das Wort "stein" enthält.

QUEST 3 - IN
--------------------------------------------------

Professor Eich sucht Pokémon bestimmter Typen:

    Elektro
    Feuer
    Wasser


Du könntest schreiben:

    WHERE typ = 'Elektro'
    OR typ = 'Feuer'
    OR typ = 'Wasser';


Das funktioniert.

Aber SQL bietet eine kürzere Möglichkeit:

    IN


Beispiel:

    SELECT *
    FROM pokemon
    WHERE typ IN ('Elektro', 'Feuer', 'Wasser');


SQL-WISSEN:

IN prüft, ob ein Wert in einer Liste vorkommt.


AUFGABE:

Zeige alle Pokémon mit folgendem Status:

    aktiv
    verletzt


Verwende dafür IN.

QUEST 5 - ALIASES MIT AS
--------------------------------------------------

Professor Eich beschwert sich über die Berichte.

"Ich möchte verständliche Überschriften!"


Mit AS kannst du Spalten im Ergebnis
einen anderen Namen geben.


Beispiel:

        name AS Pokemon,
        typ AS Pokemon_Typ,
        level AS Level

WICHTIG:

AS verändert nicht den echten Namen der Spalte
in der Datenbank.

Es verändert nur die Anzeige des Ergebnisses.

QUEST 7 - CASE WHEN
--------------------------------------------------

Professor Eich möchte die Pokémon automatisch
nach ihrem Level bewerten.


Die Regeln:

    Level 1 bis 3  = Anfänger
    Level 4 bis 5  = Nachwuchs
    Level 6 bis 8  = Erfahren
    Level 9+       = Meister


Dafür gibt es CASE WHEN.


Beispiel:

    SELECT
        name,
        level,
        CASE
            WHEN level <= 3 THEN 'Anfänger'
            WHEN level <= 5 THEN 'Nachwuchs'
            WHEN level <= 8 THEN 'Erfahren'
            ELSE 'Meister'
        END AS rang
    FROM pokemon;


SQL-WISSEN:

CASE funktioniert ähnlich wie:

    Wenn Bedingung A stimmt, dann Wert A.
    Wenn Bedingung B stimmt, dann Wert B.
    Sonst ein anderer Wert.

Bewerte die Stärke der Pokémon.


Regeln:

    unter 80 Stärke
    = Schwach

    80 bis 119 Stärke
    = Trainiert

    120 bis 179 Stärke
    = Stark

    ab 180 Stärke
    = Legendär


Gib aus:

    name
    staerke
    staerkeklasse

QUEST 8 - MEHRERE JOINS
--------------------------------------------------

Jetzt wird es ernst.

Professor Eich möchte gleichzeitig wissen:

Welches Pokémon hat welche Mission
und welches Item ist ihm zugeordnet?


Wir müssen jetzt drei Tabellen verbinden:

    pokemon
    missionen
    items


Beispiel:

    SELECT
        pokemon.name,
        missionen.titel,
        items.name
    FROM pokemon
    JOIN missionen
    ON pokemon.id = missionen.pokemon_id
    JOIN items
    ON pokemon.id = items.pokemon_id;


SQL-WISSEN:

Du kannst mehrere JOINs in einer Abfrage verwenden.


AUFGABE:

Erstelle einen Bericht mit:

    Name des Pokémon
    Typ
    Mission
    Belohnung
    Item
    Wert des Items


--------------------------------------------------
QUEST 9 - TABELLEN-ALIASES
--------------------------------------------------

Unsere Abfragen werden langsam ziemlich lang.

Statt ständig:

    pokemon.name
    missionen.titel
    items.name

zu schreiben, können Tabellen ebenfalls
Aliases bekommen.


Beispiel:

    SELECT
        p.name,
        m.titel
    FROM pokemon AS p
    JOIN missionen AS m
    ON p.id = m.pokemon_id;


Jetzt steht:

    p

für:

    pokemon


Und:

    m

für:

    missionen


AUFGABE:

Verbinde alle drei Tabellen erneut.


Verwende:

    p = pokemon
    m = missionen
    i = items


Gib aus:

    p.name
    m.titel
    i.name


--------------------------------------------------
QUEST 10 - TRANSAKTIONEN
--------------------------------------------------

Professor Eich muss eine größere Änderung
an der Datenbank durchführen.

Alle aktiven Pokémon sollen 25 zusätzliche
Stärkepunkte erhalten.

Doch was passiert, wenn dabei ein Fehler gemacht wird?


Dafür gibt es Transaktionen.


Ein vereinfachtes Beispiel:

    START TRANSACTION;

    UPDATE pokemon
    SET staerke = staerke + 25
    WHERE status = 'aktiv';


Jetzt wurde die Änderung innerhalb der
Transaktion durchgeführt.

Sie kann bestätigt werden mit:

    COMMIT;


Oder rückgängig gemacht werden mit:

    ROLLBACK;


SQL-WISSEN:

COMMIT bedeutet:

    Änderungen endgültig bestätigen.


ROLLBACK bedeutet:

    Änderungen der aktuellen Transaktion
    rückgängig machen.


WICHTIG:

Die genaue Syntax für Transaktionen kann je nach
Datenbanksystem etwas unterschiedlich sein.

--------------------------------------------------
GEHEIM-QUEST - WAS IST SQL INJECTION?
--------------------------------------------------

Nach dem Angriff untersucht Professor Eich
die Nachricht von Bobby Tables.

Sie sah ungefähr so aus:

    Robert'); DROP TABLE pokemon;--


Das Problem dahinter heißt:

    SQL Injection


SQL Injection kann entstehen, wenn ein Programm
Benutzereingaben unsicher direkt in SQL-Befehle einfügt.


Vereinfacht gesagt:

Ein Programm erwartet zum Beispiel einen Namen.

Ein Angreifer versucht stattdessen,
Teile eines SQL-Befehls einzugeben.


Deshalb sollte man SQL-Abfragen in echten Anwendungen
nicht einfach durch das Zusammenkleben von
Texteingaben bauen.


Stattdessen verwendet man normalerweise:

    Prepared Statements

oder:

    parametrisierte Abfragen


Beispielidee:

    SELECT *
    FROM pokemon
    WHERE name = ?;


Das ? steht für einen Wert, der später sicher
übergeben wird.


WICHTIG:

Wie Parameter genau geschrieben werden,
hängt von der Programmiersprache und Datenbank ab.

ABSCHLUSS-QUEST
--------------------------------------------------

Ordne die SQL-Begriffe der richtigen Erklärung zu:


    1. DISTINCT

    2. LIKE

    3. IN

    4. BETWEEN

    5. AS

    6. CASE

    7. COMMIT

    8. ROLLBACK


ERKLÄRUNGEN:

    A = Änderungen einer Transaktion rückgängig machen

    B = Werte innerhalb eines Bereichs suchen

    C = doppelte Ergebnisse entfernen

    D = mehrere mögliche Werte prüfen

    E = Änderungen einer Transaktion bestätigen

    F = Alias bzw. Anzeigenamen vergeben

    G = Textmuster suchen

    H = Bedingungen verwenden, um unterschiedliche
        Werte auszugeben


Schreibe die Lösung zum Beispiel so:

    1 = ?
    2 = ?
    3 = ?
    4 = ?
    5 = ?
    6 = ?
    7 = ?
    8 = ?
